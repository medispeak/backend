# Medispeak v2 API

The v2 API is the asynchronous, metered, multi-tenant public API. A client
account uploads audio to a **scribe session**, commits it for processing, and
then receives results either by polling the session or via a signed webhook.

All endpoints live under `/api/v2`, speak JSON, and are authenticated with a
Bearer token. The controllers are in `app/controllers/api/v2/`.

---

## Authentication

Send your API token as a Bearer token:

```
Authorization: Bearer msk_live_xxxxxxxxxxxxxxxxxxxxxxxx
```

Tokens are minted per account (`ApiToken`). The raw token is shown **once** at
creation time; the server stores only a SHA-256 digest and matches incoming
tokens against it (`ApiToken.authenticate`). The digest lookup also enforces the
token's `active` flag and `expires_at`, so a deactivated or expired token fails
authentication.

- Token prefix: `msk_live_` (the first 12 characters are kept as `token_prefix`
  for display; the full secret is never persisted in plaintext).
- A missing or invalid token returns **401 Unauthorized** (empty body — the
  `authenticate_api_token!` before_action calls `head :unauthorized`).

Every v2 endpoint is scoped to the token's account. Sessions are looked up via
`ScribeSession.where(account: current_account)`, so a session id belonging to a
different account returns **404**, not 403.

---

## Error envelope

Most v2 errors use a stable envelope (`render_error` in
`Api::V2::BaseController`):

```json
{
  "error": {
    "code": "session_not_found",
    "message": "Scribe session not found",
    "request_id": "a1b2c3d4-...",
    "details": {}
  }
}
```

| Code                 | Typical status | Meaning |
|----------------------|----------------|---------|
| `validation_error`   | 422 / 409      | Bad `outputs`, or an `Idempotency-Key` reused with a different payload (409). |
| `session_not_found`  | 404            | Session id not found within the caller's account. |
| `session_expired`    | 410            | Upload/commit attempted on an expired session. |
| `rate_limited`       | 429            | Per-account rate limit exceeded (see Rate limiting). |

Note: the **401 Unauthorized** path returns an empty body rather than the
envelope. Uncaught server errors are caught by the global handler and return a
static `internal_error` message (raw exception text is logged, never returned).

## Session lifecycle

```
create  ─►  upload audio  ─►  commit  ─►  poll (GET :id)  /  webhook
(201)       (200)             (202)        (200/202/206)
```

1. **Create** a session declaring the `outputs` you want.
2. **Upload** one or more audio files to the session.
3. **Commit** the session — this is the billable, idempotent operation that
   places a quota hold and enqueues background processing.
4. **Poll** `GET /api/v2/scribe_sessions/:id` until the status is terminal, or
   receive the completion **webhook** if you set a `callback_url`.

A session expires 24 hours after creation (`expires_at`). Uploading or
committing an expired session returns 410 `session_expired`.

Session `status` values (`ScribeSession` enum): `created`, `uploading`,
`processing`, `completed`, `partial`, `failed`, `expired`.

## Endpoints

### POST /api/v2/scribe_sessions — create

Creates a session. The body declares the desired `outputs`. Each output is one
of:

- `{ "type": "transcript" }` — echo the source-language transcript text.
- `{ "type": "form", "page_id": <id>, "context": {...} }` — structure the
  transcript against a Page's form fields. `page_id` is **required** and must
  reference an existing `Page`.
- `{ "type": "note", "template_ref": "<prompt>", "page_id": <id> }` — produce a
  free-text clinical note. The note prompt is `template_ref` if present,
  otherwise the page's `prompt`.

**Body fields** (permitted params):

| Field           | Type   | Notes |
|-----------------|--------|-------|
| `outputs`       | array  | Required, non-empty. Each item: `type`, `page_id`, `template_ref`, `context`. |
| `modality`      | string | `audio` (default, ASR) or `document` (lab-report OCR — upload via `/documents`). |
| `language_hint` | string | Stored as the session `language` (e.g. `en`, `hi`, `ta`, `auto`). |
| `mode`          | string | `consultation` (default) or `dictation`. |
| `callback_url`  | string | If set, a webhook is delivered on completion. |

**Responses**

- **201 Created** — returns the serialized session (see [Session object](#session-object)).
- **422 validation_error** — `outputs` blank/empty, an unknown output `type`,
  or a `form` output whose `page_id` does not reference an existing page.

Request:

```bash
curl -X POST https://api.medispeak.example/api/v2/scribe_sessions \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 2f0c...create" \
  -d '{
    "language_hint": "en",
    "mode": "consultation",
    "callback_url": "https://app.example.com/medispeak/webhook",
    "outputs": [
      { "type": "transcript" },
      { "type": "form", "page_id": 42, "context": { "visit": "follow-up" } },
      { "type": "note", "template_ref": "Write a SOAP note." }
    ]
  }'
```

Response (201):

```json
{
  "id": 1001,
  "status": "created",
  "mode": "consultation",
  "language": "en",
  "expires_at": "2026-06-26T10:00:00.000Z",
  "outputs": [
    { "id": 5001, "type": "transcript", "status": "pending", "result": null, "errors": null },
    { "id": 5002, "type": "form",       "status": "pending", "result": null, "errors": null },
    { "id": 5003, "type": "note",       "status": "pending", "result": null, "errors": null }
  ]
}
```

### POST /api/v2/scribe_sessions/:id/audio — upload audio

Attaches an audio file to the session and moves it to `uploading`. The file is
sent as multipart form-data under the field name `audio`.

**Responses**

- **200 OK** — `{ "id": <id>, "status": "uploading" }`.
- **404 session_not_found** — unknown id (or another account's id).
- **410 session_expired** — the session has passed `expires_at`.

```bash
curl -X POST https://api.medispeak.example/api/v2/scribe_sessions/1001/audio \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -F "audio=@consultation.m4a"
```

```json
{ "id": 1001, "status": "uploading" }
```

You may upload more than once; the orchestrator processes the first attached
audio blob.

---

### POST /api/v2/scribe_sessions/:id/documents — upload a document (OCR)

For sessions created with `"modality": "document"`. Attaches **one** lab-report
document (multipart field `document`) and moves the session to `uploading`.

**Limits**, all enforced server-side under a row lock, so concurrent uploads
cannot slip past them:

| Limit | Value |
| --- | --- |
| Content types | `application/pdf`, `image/jpeg`, `image/png`, `image/webp` |
| Per file | 10 MB |
| Per session | 20 MB, 20 pages |

Pages are counted at upload time by walking the PDF's page tree, so a file
cannot understate itself through its self-declared `/Count`; if `/Count`
claims *more* pages than the tree holds, the larger number is used, so an
inconsistent file is never billed for less than it declares. An image counts
as one page. An encrypted, malformed, or hostile PDF is a clean **422**
rather than a slow failure at commit. The response's `pages` is the running
session total, so it is also the quantity your per-page cost is based on.

**Multiple files are one document.** Call this endpoint once per file, *in
order and sequentially* — a report photographed a page at a time is transcribed
in upload order. Racing the calls is safe but shuffles the pages.

At commit, a vision model extracts the complete document text in a single call
across every attached file. That text is persisted as the session's
`transcript` — the audit trail of what the model actually read — and the
declared outputs are then structured from it exactly as for audio. An
extraction that hits the model's output budget is a **failure**, never a
truncated transcript: a partial lab report that reads as complete is worse than
no result. Re-commit to retry it.

**Responses**

- **200 OK** — `{ "id": <id>, "status": "uploading", "pages": <running total> }`.
- **404 session_not_found** — unknown id (or another account's id).
- **409 validation_error** — the session's modality is `audio` (and vice versa:
  the audio endpoints 409 on a `document` session), or its status is past
  `uploading`.
- **410 session_expired** — the session has passed `expires_at`.
- **422 validation_error** — missing `document` field, unsupported content type,
  a single file over the 10 MB per-file limit, or a PDF that could not be read.
- **422 document_upload_failed** — the upload would take the session over its
  cumulative byte or page ceiling. The upload is rejected whole; the session's
  `pages` does not move.

```bash
curl -X POST https://api.medispeak.example/api/v2/scribe_sessions/1001/documents \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -F "document=@lab_report.pdf"
```

```json
{ "id": 1001, "status": "uploading", "pages": 3 }
```

### POST /api/v2/scribe_sessions/:id/commit — commit

The canonical **billable, idempotent** operation. It places a quota hold
(`Metering::QuotaGuard.hold!`), sets the session to `processing`, and enqueues
`ProcessScribeSessionJob`.

**Responses**

- **202 Accepted** — returns the serialized session with `status: "processing"`.
- **404 session_not_found** / **410 session_expired** — as above.

Commit uses an internal idempotency fingerprint of `commit:<session_id>` in
addition to any `Idempotency-Key` header, so a duplicate commit replays the
prior response rather than re-enqueuing.

```bash
curl -X POST https://api.medispeak.example/api/v2/scribe_sessions/1001/commit \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -H "Idempotency-Key: 2f0c...commit"
```

```json
{
  "id": 1001,
  "status": "processing",
  "mode": "consultation",
  "language": "en",
  "expires_at": "2026-06-26T10:00:00.000Z",
  "outputs": [ ... ]
}
```

### GET /api/v2/scribe_sessions/:id — poll / show

Returns the serialized session. The **HTTP status encodes progress** so a
polling client can branch on the status line alone (`status_for`):

| Session status         | HTTP status        |
|------------------------|--------------------|
| `completed`, `failed`  | **200 OK**         |
| `partial`              | **206 Partial Content** |
| anything else (`created`, `uploading`, `processing`) | **202 Accepted** |

- **404 session_not_found** — unknown id / cross-account id.

```bash
curl https://api.medispeak.example/api/v2/scribe_sessions/1001 \
  -H "Authorization: Bearer $MSK_TOKEN"
```

Response once processing completes (200):

```json
{

  "status": "completed",
  "mode": "consultation",
  "language": "en",

      "id": 5001,
```

### GET /api/v2/usage — usage summary

Aggregates the account's **finalized** usage events. See
[metering-and-billing.md](../metering-and-billing.md) for the full model.

Optional params (all backward compatible):

| Param       | Notes |
|-------------|-------|
| `from`/`to` | ISO8601 window bounds (default: all time). |
| `scope=subtree` | Aggregate the account's whole tenancy subtree (default: this account only). |

| `group_by=user\|account` | Adds a `by_user` / `by_account` array shaped like `by_model`. |

```json

  "total_tokens": 4210,
  "total_audio_seconds": 95.0,

    { "model": "whisper-1",   "cost": 0.0095, "total_tokens": 0,    "audio_seconds": 95.0 },
```

## Session object

`ScribeSessionSerializer` shapes every session response:

```json
{
  "id": 1001,
  "status": "completed",
  "mode": "consultation",
  "modality": "document",
  "language": "en",
  "created_at": "2026-06-26T09:00:00.000Z",
  "expires_at": "2026-06-26T10:00:00.000Z",
  "transcript": { "text": "Hemoglobin | 13.5 | g/dL | 12–16", "language": "en" },
  "outputs": [ <output>, ... ],
  "usage": {
    "cost": 0.0142,
    "total_tokens": 1320,
    "audio_seconds": 0.0,
    "pages": 3,
    "by_function": { "ocr": 0.0121, "structuring": 0.0021 }
  }
}
```

| Field | Description |
| --- | --- |
| `modality` | `audio` or `document`. Fixed at creation. |
| `transcript` | The extracted source text — OCR output for a `document` session, ASR output for an `audio` one — as `{ text, language }`, or `null` before it exists. **This is the top-level way to read OCR output**; it does not depend on having declared a `transcript` output. During an audio recording it carries the growing live transcript instead. |
| `usage` | Per-session metering. `pages` is the quantity OCR is billed on; `audio_seconds` is the audio equivalent, and each is `0` for the other modality. `by_function` splits cost across `ocr` / `asr` / `structuring`. |

Failed attempts (a provider response that was billed but could not be used —
a truncated extraction, say) are kept in the account ledger for our own
accounting but are **not** charged to your credits and **not** included in this
`usage` object, so a run that produced nothing costs you nothing and reads that
way.

### Output object

| Field    | Description |
|----------|-------------|
| `id`     | Output id. |
| `type`   | `transcript`, `form`, or `note`. |
| `status` | `pending`, `success`, `partial`, or `failure`. |
| `result` | The produced data (shape depends on `type`, see below). May be `null` until processed. |
| `errors` | Per-output error list, or `null`. Maps to the model's `result_errors` column (the public key is `errors`). |

**Result shapes by type:**

- `transcript` → `{ "text": "...", "language": "en" }`
- `form` → the structured object keyed by field friendly names, e.g.
  `{ "chief_complaint": "Headache", "duration_days": 3 }`. If structuring
  produced output that failed validation, `status` is `partial` and `errors`
  carries the validation messages while `result` still holds the best-effort
  structured data.
- `note` → `{ "note": "<free text>" }`

**Per-output isolation:** each output is processed independently. One output
failing does not abort its siblings. The session status rolls up to:

- `completed` — every output succeeded,
- `failed` — every output failed (including the case where ASR itself failed,
  which fails all outputs), or
- `partial` — any mix of success and non-success.

## Idempotency

Send an `Idempotency-Key` header on `create` and `commit` to make retries safe.
Behavior (`with_idempotency` in `Api::V2::BaseController`):

- **No header** → the request runs normally with no idempotency bookkeeping.
- **Same key, same request payload** → the stored response is replayed verbatim
  (same body and status).
- **Same key, different request payload** → **409** `validation_error`
  ("Idempotency-Key reuse with a different request payload").
- Stored idempotency records are retained ~24h.

The fingerprint for `create` is a SHA-256 of the raw request body; for `commit`
it is `commit:<session_id>`. Keys are scoped per API token.

## Rate limiting

Throttling is enforced by `rack-attack`, keyed on the resolved **account id**
(not the bearer token, so minting more tokens does not raise the cap). Config is
in `config/initializers/rack_attack.rb`.

- Budget: the account's `settings["rpm"]` requests over a 60-second window
  (default **120 rpm**).
- Only `/api/` paths with a valid token are throttled; unauthenticated or
  non-API requests fall through.

On exceeding the limit the responder returns **429** with these headers and a
JSON body:

```
RateLimit-Limit: 120
RateLimit-Remaining: 0
RateLimit-Reset: <epoch-seconds>
Retry-After: <seconds-until-reset>
```

```json
{ "error": { "code": "rate_limited", "message": "Rate limit exceeded" } }
```

Note: the rack-attack 429 body does **not** include `request_id`/`details` — it
is emitted at the middleware layer before the controller envelope.

## Webhooks

If a session has a `callback_url`, `ProcessScribeSessionJob` enqueues
`ScribeWebhookJob` after processing, which POSTs a **PHI-light** completion
notification.

### Payload

The body is an explicit allowlist — **no transcript text and no field values**.
Consumers must fetch full results via the authenticated `GET` endpoint.

```json
{
  "session_id": 1001,
  "status": "completed",
  "outputs": [
    { "id": 5001, "output_type": "transcript", "status": "success" },
    { "id": 5002, "output_type": "form",       "status": "success" },
    { "id": 5003, "output_type": "note",       "status": "success" }
  ],
  "delivery_id": "0f1e2d3c-....",
  "sent_at": "2026-06-25T10:05:00Z"
}
```

`delivery_id` is a fresh UUID per delivery attempt. Delivery is at-least-once
(Faraday transport errors are logged and swallowed so the job can be retried), so
**consumers must dedupe on `delivery_id`**.

### Signature

The request carries:

```
X-Medispeak-Signature: t=<unix>,v1=<hex>
```

where `v1 = HMAC-SHA256(account.webhook_secret, "<t>.<raw_body>")` — the HMAC is
computed over the **raw JSON body bytes** with the timestamp prefixed
(`<timestamp>.<raw_body>`). Verify against the raw body you received; do not
re-serialize the parsed JSON before verifying. (See `Scribe::WebhookSigner`.)

#### Verify in Ruby

```ruby
require "openssl"

def verify_medispeak_webhook(raw_body, header, secret, tolerance: 300)
  parts = header.to_s.split(",").map { |p| p.split("=", 2) }.to_h
  t  = parts["t"].to_i
  v1 = parts["v1"].to_s

  # Reject future-dated or stale timestamps.
  now = Time.now.to_i
  return false if (now - t).abs > tolerance

  expected = OpenSSL::HMAC.hexdigest("SHA256", secret, "#{t}.#{raw_body}")
  ActiveSupport::SecurityUtils.secure_compare(expected, v1)
end
```

#### Verify in Node

```js
const crypto = require("crypto");

function verifyMedispeakWebhook(rawBody, header, secret, toleranceSec = 300) {
  const parts = Object.fromEntries(
    header.split(",").map((p) => p.split("=", 2))
  );
  const t = parseInt(parts.t, 10);
  const v1 = parts.v1 || "";

  const now = Math.floor(Date.now() / 1000);
  if (Math.abs(now - t) > toleranceSec) return false;

  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${t}.${rawBody}`)
    .digest("hex");

  const a = Buffer.from(expected);
  const b = Buffer.from(v1);
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

Make sure your web framework gives you the **raw request body** (not a re-encoded
JSON object) for verification.

## Full flow (curl)

```bash
MSK_TOKEN=msk_live_xxxxxxxxxxxxxxxxxxxxxxxx
BASE=https://api.medispeak.example

# 1. Create
SESSION=$(curl -s -X POST "$BASE/api/v2/scribe_sessions" \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"language_hint":"en","outputs":[{"type":"transcript"},{"type":"form","page_id":42}]}')
ID=$(echo "$SESSION" | jq -r .id)

# 2. Upload audio
curl -s -X POST "$BASE/api/v2/scribe_sessions/$ID/audio" \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -F "audio=@consultation.m4a"

# 3. Commit (billable, idempotent)
curl -s -X POST "$BASE/api/v2/scribe_sessions/$ID/commit" \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -H "Idempotency-Key: $(uuidgen)"

# 4. Poll until 200/206 (HTTP 202 means still processing)
curl -s -i "$BASE/api/v2/scribe_sessions/$ID" \
  -H "Authorization: Bearer $MSK_TOKEN"
```

### Document (OCR) flow

Identical apart from steps 1 and 2: declare `"modality": "document"` at create,
and upload files instead of audio. Commit, polling, output shapes and billing
are the same path.

```bash
# 1. Create a document session
SESSION=$(curl -s -X POST "$BASE/api/v2/scribe_sessions" \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"modality":"document","outputs":[{"type":"form","page_id":42}]}')
ID=$(echo "$SESSION" | jq -r .id)

# 2. Upload each file, one call each, IN PAGE ORDER and sequentially
for f in page1.jpg page2.jpg page3.jpg; do
  curl -s -X POST "$BASE/api/v2/scribe_sessions/$ID/documents" \
    -H "Authorization: Bearer $MSK_TOKEN" \
    -F "document=@$f"
done

# 3 & 4. Commit and poll, exactly as above. The extracted text arrives as
#        the session's top-level `transcript`.
curl -s -X POST "$BASE/api/v2/scribe_sessions/$ID/commit" \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -H "Idempotency-Key: $(uuidgen)"

curl -s "$BASE/api/v2/scribe_sessions/$ID" \
  -H "Authorization: Bearer $MSK_TOKEN" | jq '.transcript, .outputs'
```
