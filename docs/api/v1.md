# Medispeak v1 API (legacy)

The v1 API is the original **synchronous, two-call** flow. It is retained as a
compatibility surface: the controllers in `app/controllers/api/v1/` are now a
thin shim over the same model-agnostic engine that powers v2. ASR runs through
`Scribe::AsrStage` and structuring through `Scribe::StructuringStage`, both
resolved from DB config (or the ENV defaults via `Llm::DefaultConfigProvider`)
exactly like v2. The public method names, response shapes, and the
`GenericException` error contract are preserved so existing v1 clients are
unaffected.

> Prefer [v2](./v2.md) for new integrations. v1 is the legacy compatibility
> layer and is slated for retirement once integrators have migrated.

---

## Authentication

v1 authenticates with the same Bearer API token as v2
(`Authorization: Bearer msk_live_...`). The token is resolved via
`ApiToken.authenticate` (digest lookup + `active`/`expires_at` enforcement) and
signs in the associated user for the request. A missing/invalid token returns
**401 Unauthorized**.

v1 actions operate on `current_user`'s own records (e.g.
`current_user.transcriptions`), so a transcription belonging to another user
returns a not-found error.

---

## Error contract

v1 errors are raised as `GenericException(message:, code:)` and rendered by the
shared `ExceptionHandler`:

```json
{
  "error": {
    "message": "Transcription not found",
    "code": "not_found",
    "request_id": "a1b2c3d4-..."
  }
}
```

Common codes: `not_found` (404), `failed_dependency` (424, used for upstream AI
or audio-upload failures). Uncaught errors return a static
`"An unexpected error occurred."` with status 500 (raw exception text is logged,
never returned).

## The two-call flow

```
POST /api/v1/pages/:page_id/transcriptions      (blocks on ASR)
        ─►  returns the transcription with transcription_text
POST /api/v1/transcriptions/:id/generate_completion   (blocks on structuring)
        ─►  returns the transcription with ai_response
```

Unlike v2, both calls are **synchronous** — they block until the provider
returns. Metering and quota now apply through the shared engine (a behavior
change from the original OpenAI-only implementation).

---

### POST /api/v1/pages/:page_id/transcriptions — create + transcribe

Creates a `Transcription` under the given page and runs ASR on the uploaded
audio in-request. Defaults to translate mode (English output) to preserve the
historical v1 behavior.

**Body** (multipart form-data), nested under `transcription`:

| Field        | Notes |
|--------------|-------|
| `audio_file` | Required. The audio upload. |
| `duration`   | Optional. |
| `context`    | Optional. Per-field context threaded into the structuring schema. |

**Responses**

- **201 Created** — the serialized transcription (includes `transcription_text`,
  `status: "transcribed"`, `audio_file_url`, and a synthesized `title`).
- **404 not_found** — the `page_id` does not exist.
- **424 failed_dependency** — audio upload or AI provider error.

```bash
curl -X POST https://api.medispeak.example/api/v1/pages/42/transcriptions \
  -H "Authorization: Bearer $MSK_TOKEN" \
  -F "transcription[audio_file]=@consultation.m4a" \
  -F "transcription[duration]=95"
```

---

### POST /api/v1/transcriptions/:id/generate_completion — structure

Runs the structuring stage against the stored transcript text using the page's
form fields and prompt, then stores the structured result on the transcription.

**Responses**

- **200 OK** — the serialized transcription with `ai_response` populated and
  `status: "completion_generated"`. Token counts (`prompt_tokens`,
  `completion_tokens`, `total_tokens`) are summed additively onto the row.
- **404 not_found** — the transcription is not the caller's.
- **424 failed_dependency** — AI provider error (the transcription is marked
  `failed`).

```bash
curl -X POST https://api.medispeak.example/api/v1/transcriptions/777/generate_completion \
  -H "Authorization: Bearer $MSK_TOKEN"
```

---

### GET /api/v1/transcriptions/:id — show

Returns a single transcription owned by the current user (404 otherwise).

### GET /api/v1/transcriptions — index

Returns the current user's transcriptions, newest first, with Pagy pagination
metadata:

```json
{
  "transcriptions": [ { ... }, ... ],
  "pagy": { "page": 1, "items": 20, "count": 137, "page_count": 7 }
}
```

## Supporting endpoints

| Method & path                          | Purpose |
|----------------------------------------|---------|
| `GET /api/v1/me`                       | Current user. |
| `DELETE /api/v1/me`                    | Delete the current user. |
| `GET /api/v1/templates/:id`            | Show an active template. |
| `GET /api/v1/templates/find_by_domain` | Resolve a template by the request's origin FQDN (`Domain` mapping). |

## Relationship to the engine

v1 and v2 share the same internals:

- ASR: `Llm::ConfigResolver.call(function: :asr, ...)` → `Scribe::AsrStage`.
- Structuring: `Llm::ConfigResolver.call(function: :structuring, ...)` →
  `Scribe::StructuringStage`.

This means model selection (per-page / per-account / system / ENV fallback) and
metering behave identically across both API versions. See
[architecture.md](../architecture.md) and
[configuration.md](../configuration.md).
