## Dependency notes

- **001 → 002 → 003** and **002 → 004** are one coherent billing workstream.
  Settle the **reserve-vs-postpaid** and **hard-block-vs-overdraft** decisions
  (raised in 002 Step 0) **before** starting 002 — 003 builds on that choice.
- **001 before 002** is *soft*: 001 gives `commit` a real duration-based estimate.
  002 also works without 001 using a zero-balance reject (documented as interim).
- **004 after 002** is *soft*: both touch the commit path and the ledger; landing
  002 first avoids a merge conflict and keeps the settlement story consistent.
- Everything 005–019 is independent — no ordering constraints between them.
- Two plans introduce a **new gem** (014 `active_storage_validations`, 010
  `bundler-audit`); if run in isolated worktrees, expect a `Gemfile.lock` conflict
  on merge — rebase-and-`bundle` rather than hand-merging the lock.

## Decision gates (do not skip)

- **002 / 003** — reserve-vs-postpaid billing model; hard-block-vs-overdraft floor.
- **013** — is the template library intentionally *shared config* or *tenant-owned*?
  Path A (add `account_id` ownership) vs Path B (restrict writes to admins).
- **011** — STOP if a gem fails to build on Ruby 3.4 (the git-pinned `administrate`
  beta is the least predictable).
- **019** — MED-confidence indexes; confirm with `EXPLAIN` at representative volume
  before committing (an `account_id`-leading index may already suffice).

## Findings surfaced but NOT planned this round

Recorded so they aren't re-audited. These were found and vetted; the maintainer
chose not to turn them into plans now.

- **example.env missing required vars** (DX) — `AR_ENCRYPTION_*`, `ANTHROPIC_API_KEY`,
  `OPENROUTER_API_KEY`; `BACKEND_PORT`→`PORT` drift. Quick doc fix; do opportunistically.
- **No root `CLAUDE.md`/`AGENTS.md`** (DX) — high-leverage for an agent-run repo; a
  one-file addition. Deferred, not rejected.
- **`administrate` pinned to git `main` beta** (DEP-03) — non-reproducible `bundle
  update` on the admin surface. Address at the next dependency review.
- **Duplicated bearer-auth across the two API base controllers** (DEBT-02) — extract
  a shared concern; low urgency, already slightly drifted.
- **Price `ORDER BY effective_at DESC` is NULLS-FIRST** (BUG-06) — latent stale-price;
  masked today because seeds always set `effective_at`. One-line `NULLS LAST` fix
  when the pricing code is next touched.
- **v1 `transcriptions#index` N+1 + `.attributes` over-fetch** (PERF-03) — same
  eager-load pattern as plan 018; fold in if v1 list latency matters.
- **~7 admin dashboards N+1** (PERF-04) — internal Administrate pages, bounded by the
  20/page default; low external impact.
- **Usage endpoint runs 4 aggregates where 1 would do** (PERF-05) — micro-optimization.
- **Four divergent serialization strategies** (DEBT-01) — real, but a larger refactor;
  converge on the plain-Ruby serializer when touching response shapes.
- **v1 create reflects upstream AWS/network error text** (SEC-10) — minor info
  disclosure; scrub to a generic message when the v1 path is next edited.
- **Wildcard CORS** (SEC-08) — low today (`credentials: false` by default); scope to
  `/api/*` and never enable credentials on the wildcard.
- **Orphaned broken `bin/delayed_job`** (DX-04) — trivial: `git rm bin/delayed_job`.

## Considered and rejected (not worth doing now)

- **Bump `ruby-openai` 6→8** — no CVE/EOL pressure, the pin is intentional and the
  adapter works; revisit only when touching the OpenAI transport.
- **Batch `ConfigResolver`'s 4 sequential lookups into one query** — runs in a
  background job at low volume; the cascade is by-design. Nice-to-have, not a win.
- **Dedupe adapter `usage_from`** — divergent by necessity (different provider key
  names); shared transport/timing is already factored into `Llm::Adapter`.

## Direction (maintainer options, not plans)

Forward-looking, grounded in the design spec — surfaced for the maintainer to weigh,
not scheduled as work:

- **D1 — Finish the billing engine into something you can charge on.** Plans 001–004
  fix the acute bugs; the fuller monetization spine (reservations, sweeper,
  reconciliation, `account_usage_daily/monthly` rollups) is designed in the spec but
  still inert.
- **D2 — Ship the TS + Ruby SDKs** (spec §7). The v2 API is stable and documented;
  a 1:1 SDK + one-call `scribe.transcribe(...)` is adoption-critical.
- **D3 — PHI retention/purge lifecycle** (spec §5.3) — expired-session audio is never
  purged today; pairs with plan 003's sweeper.
- **D4 — CombinedStage + capability routing + Gemini adapter** (spec §4.5, deferred) —
  flags already ship; the orchestrator is cascade-only.
